BPMT Lite API Docs

v1.7.0 动态表结构 API 与动态表视图 API。文档公开访问，业务接口需要 HMAC 请求头。

入口

OpenAPI JSON：/api/openapi.json

业务前缀：/api/v1

签名

请求头：X-BPMT-App-Key、X-BPMT-Timestamp、X-BPMT-Nonce、X-BPMT-Signature。

canonical = METHOD + "\n"
  + PATH + "\n"
  + NORMALIZED_QUERY + "\n"
  + TIMESTAMP + "\n"
  + NONCE + "\n"
  + SHA256_HEX(BODY)

signature = HEX(HMAC_SHA256(APP_SECRET, canonical))

PATH 使用公开请求 URI，例如 /api/v1/dynamic-table-views。NORMALIZED_QUERY 按解码后的参数名和值排序后再编码。

每个 curl 示例都需要按当前 METHOD、PATH、QUERY 和 BODY 重新计算 X-BPMT-Signature，不能复用其它请求的签名。

sign_request() {
  METHOD="$1"
  PATH="$2"
  QUERY="${3:-}"
  BODY_FILE="${4:-}"
  if [ -n "$BODY_FILE" ]; then
    BODY="$(cat "$BODY_FILE")"
  else
    BODY=""
  fi
  TIMESTAMP="$(date +%s)"
  NONCE="demo-$TIMESTAMP"
  BODY_HASH="$(printf '%s' "$BODY" | shasum -a 256 | awk '{print $1}')"
  CANONICAL="$(printf '%s\n%s\n%s\n%s\n%s\n%s' "$METHOD" "$PATH" "$QUERY" "$TIMESTAMP" "$NONCE" "$BODY_HASH")"
  SIGNATURE="$(printf '%s' "$CANONICAL" | openssl dgst -sha256 -hmac "$APP_SECRET" | awk '{print $NF}')"
}

动态表视图 API

只管理 dyn 动态表视图，只维护 /{viewKey}.view 对应视图配置；不纳入菜单、首页、按钮入口等导航配置。

删除视图不会删除动态表和业务数据，也不会删除日志表或日志数据。

方法 路径 说明 风险
GET /api/v1/dynamic-table-views 分页列出 dyn 视图。 x-bpmt-risk-level=read
POST /api/v1/dynamic-table-views?dryRun=true 创建视图；dryRun 为 query 参数。 写元数据，不执行 DDL，高风险
POST /api/v1/dynamic-table-views:validate 校验并规范化快照，不落库。 x-bpmt-risk-level=read
GET /api/v1/dynamic-table-views/{viewKey} 导出完整快照；返回的 snapshot 可作为 PUT baseline。 x-bpmt-risk-level=read
PUT /api/v1/dynamic-table-views/{viewKey}?dryRun=true 完整替换视图配置。 写元数据，不执行 DDL，高风险
PATCH /api/v1/dynamic-table-views/{viewKey}/{section}?dryRun=true 局部替换一个 section，可选 base、fields、queries、limits、processors、variables、subviews、buttons、weixin、scripts。 写元数据，不执行 DDL，高风险
DELETE /api/v1/dynamic-table-views/{viewKey}?confirmViewKey=CRM_CUSTOMER_VIEW 删除视图配置，需要确认参数。 写元数据，不执行 DDL，高风险

写接口在 OpenAPI 中均标注 x-bpmt-writes-metadata=true、x-bpmt-executes-ddl=false、x-bpmt-risk-level=high。

报表视图 API

只管理 rep_list 报表视图配置，对应 /{viewKey}.view、VW_URL 与 VW_REPORT* 元数据；不管理菜单、首页卡片、外部入口或报表业务数据。

API 不执行 SQL、按钮动作或客户端脚本，只做结构校验、风险提示和元数据写入。调用方必须用真实业务页面或验收脚本确认 SQL 语义、结果列、权限过滤和运行性能。

HMAC canonical PATH 必须使用公开请求 URI，例如 /api/v1/report-views、/api/v1/report-views:validate，不能只签 /v1/report-views。

方法 路径 说明 风险
GET /api/v1/report-views 分页列出 rep_list 报表视图。 x-bpmt-risk-level=read
POST /api/v1/report-views?dryRun=true 创建报表视图；dryRun 为 query 参数。 写元数据，不执行 DDL，高风险
POST /api/v1/report-views:validate 校验完整快照，不落库。 x-bpmt-risk-level=read
GET /api/v1/report-views/{viewKey} 导出完整快照；返回的 snapshot 可作为 PUT baseline。 x-bpmt-risk-level=read
PUT /api/v1/report-views/{viewKey}?dryRun=true 完整替换报表视图配置。 写元数据，不执行 DDL，高风险
PATCH /api/v1/report-views/{viewKey}/{section}?dryRun=true 局部替换一个 section，可选 base、columns、queries、limits、variables、subviews、buttons、weixin、scripts。 写元数据，不执行 DDL，高风险
DELETE /api/v1/report-views/{viewKey}?confirmViewKey=SALES_REPORT 删除报表视图配置，需要确认参数；不删除业务数据。 写元数据，不执行 DDL，高风险

写接口在 OpenAPI 中均标注 x-bpmt-writes-metadata=true、x-bpmt-executes-ddl=false、x-bpmt-risk-level=high。GET 和 validate 不写元数据。

报表视图示例

POST /api/v1/report-views:validate 适合在生成配置后先做结构校验和风险扫描。

sign_request "POST" "/api/v1/report-views:validate" "" "report-view-snapshot.json"

curl -sS "$BASE_URL/v1/report-views:validate" \
  -H "X-BPMT-App-Key: $APP_KEY" \
  -H "X-BPMT-Timestamp: $TIMESTAMP" \
  -H "X-BPMT-Nonce: $NONCE" \
  -H "X-BPMT-Signature: $SIGNATURE" \
  -H "Content-Type: application/json" \
  --data @report-view-snapshot.json

PATCH /api/v1/report-views/SALES_REPORT/columns?dryRun=true 只替换展示列、分割线和列表顺序，并返回写入计划。

sign_request "PATCH" "/api/v1/report-views/SALES_REPORT/columns" "dryRun=true" "report-columns.json"

curl -sS "$BASE_URL/v1/report-views/SALES_REPORT/columns?$QUERY" \
  -X PATCH \
  -H "X-BPMT-App-Key: $APP_KEY" \
  -H "X-BPMT-Timestamp: $TIMESTAMP" \
  -H "X-BPMT-Nonce: $NONCE" \
  -H "X-BPMT-Signature: $SIGNATURE" \
  -H "Content-Type: application/json" \
  --data @report-columns.json

删除报表视图需要显式确认：

sign_request "DELETE" "/api/v1/report-views/SALES_REPORT" "confirmViewKey=SALES_REPORT"

curl -sS "$BASE_URL/v1/report-views/SALES_REPORT?$QUERY" \
  -X DELETE \
  -H "X-BPMT-App-Key: $APP_KEY" \
  -H "X-BPMT-Timestamp: $TIMESTAMP" \
  -H "X-BPMT-Nonce: $NONCE" \
  -H "X-BPMT-Signature: $SIGNATURE"

稳定错误码包括 REPORT_VIEW_NOT_FOUND、REPORT_VIEW_NOT_REP_LIST、REPORT_VIEW_ALREADY_EXISTS、REPORT_VIEW_INVALID_SNAPSHOT、REPORT_VIEW_CONFIRM_REQUIRED、REPORT_VIEW_UNSUPPORTED_PERMISSION、REPORT_VIEW_UNSUPPORTED_SECTION、REPORT_VIEW_INVALID_SQL_CONFIG、REPORT_VIEW_INVALID_SCRIPT_CONFIG。

风险提示码包括 SQL_SCRIPT_PRESENT、CLIENT_SCRIPT_PRESENT、BUTTON_ACTION_PRESENT、EXTERNAL_DB_KEY_PRESENT、UNEXECUTED_SQL_SEMANTICS。

validate 与 dryRun

POST /api/v1/dynamic-table-views:validate 只做校验、默认值规范化、脚本风险扫描和权限限制检查。

sign_request "POST" "/api/v1/dynamic-table-views:validate" "" "view-snapshot.json"

curl -sS "$BASE_URL/v1/dynamic-table-views:validate" \
  -H "X-BPMT-App-Key: $APP_KEY" \
  -H "X-BPMT-Timestamp: $TIMESTAMP" \
  -H "X-BPMT-Nonce: $NONCE" \
  -H "X-BPMT-Signature: $SIGNATURE" \
  -H "Content-Type: application/json" \
  --data @view-snapshot.json

dryRun=true 用于创建、替换和局部 patch，返回 plan.dryRun=true 与写入计划，但不写入配置。

sign_request "PATCH" "/api/v1/dynamic-table-views/CRM_CUSTOMER_VIEW/fields" "dryRun=true" "fields-section.json"

curl -sS "$BASE_URL/v1/dynamic-table-views/CRM_CUSTOMER_VIEW/fields?$QUERY" \
  -X PATCH \
  -H "X-BPMT-App-Key: $APP_KEY" \
  -H "X-BPMT-Timestamp: $TIMESTAMP" \
  -H "X-BPMT-Nonce: $NONCE" \
  -H "X-BPMT-Signature: $SIGNATURE" \
  -H "Content-Type: application/json" \
  --data @fields-section.json

权限与风险

只有底层 dyn HBM 有 PRI 的字段、分割线、限制、子视图、按钮、微信等支持 permissions。

查询、变量、处理器 permissions 会被校验拒绝，返回 UNSUPPORTED_PERMISSION。

脚本字段会进行风险扫描。包含删除、反射、进程执行、文件操作等高风险脚本时，应先使用 validate 或 dryRun=true 获取 warnings，再人工复核。

删除视图需要显式确认：

sign_request "DELETE" "/api/v1/dynamic-table-views/CRM_CUSTOMER_VIEW" "confirmViewKey=CRM_CUSTOMER_VIEW"

curl -sS "$BASE_URL/v1/dynamic-table-views/CRM_CUSTOMER_VIEW?$QUERY" \
  -X DELETE \
  -H "X-BPMT-App-Key: $APP_KEY" \
  -H "X-BPMT-Timestamp: $TIMESTAMP" \
  -H "X-BPMT-Nonce: $NONCE" \
  -H "X-BPMT-Signature: $SIGNATURE"
