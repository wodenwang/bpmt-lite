# bpmt-lite v2.0.0 桌面端 UI 现代化大版本设计

> 状态：本文中的 CSS-only 现代主题优先路线已被后续 Product Design 复盘修正。新的执行方向见 `docs/v2.0.0/desktop-admin-clarity-replan.md` 和 `docs/superpowers/specs/2026-06-11-bpmt-lite-v1.8.0-desktop-admin-clarity-design.md`。本文保留为旧规划背景，不再作为直接实现依据。

## 版本定位

`v2.0.0` 是 `bpmt-lite` 的桌面端 UI 现代化大版本。它不以升级前端技术栈为目标，而是把现有 JSP、jQuery UI、zTree、chosen、低代码控件和动态视图体系包上一层更现代、更一致、更可维护的视觉与交互基线。

本大版本的核心目标是：在尽量不触碰业务逻辑、不重写低代码控件、不改变动态视图配置模型的前提下，把桌面后台从“历史 jQuery UI 皮肤”提升到“符合当前后台产品审美的工作台界面”。

## 背景判断

当前桌面端 UI 的老化主要来自全局视觉基线，而不是单个业务模块：

- `platform/src/main/webapp/css/styles.css` 直接定义全局 `body` 为 12px Arial，并把 `input` 固定为 200x20。
- `platform/src/main/webapp/css/frame.css` 固定了 30px topbar、250px 左侧菜单、固定 footer 和旧式页面壳。
- `platform/src/main/webapp/include/html_include.jsp` 全局引入 jQuery UI theme、`jquery-ui-ext.css`、`styles.css`、`styles_light/dark.css`，这是最适合插入现代化覆盖层的位置。
- `Core.init` 会统一初始化 `table.ws-table`、`button`、`div.ws-bar`、`select.chosen`、`ztree` 等控件，说明低成本覆盖可以覆盖大量页面。
- 业务页面大量使用 `ws-table`、`ws-panel`、`ws-bar`、`ui-button`、`chosen`、`ztree`，适合建立“旧选择器上的新视觉规范”。

因此，`v2.0.0` 不应从重写前端开始，而应采用“设计系统覆盖层 + 高价值页面验证 + 小版本渐进落地”的路线。

## 用户与使用场景

目标用户：

- 系统管理员：高频使用功能设置、用户权限、第三方系统、动态表开发、流程设置。
- 业务管理员：高频使用我的事项、待办、报表、动态表列表、流程办理。
- 外部集成开发者：使用 API 文档、第三方系统 OAuth 接入提示词、OpenAPI。

典型桌面任务：

- 登录并进入某个业务域。
- 在左侧树形菜单中定位功能。
- 在列表页搜索、筛选、分页、查看行操作。
- 在表单页编辑配置并保存。
- 在弹窗中复制、确认、提交或关闭。
- 在动态表/报表/流程设置中处理密集字段和复杂配置。

本版本不覆盖移动端、小屏幕 H5、微信生态页面。

## 设计原则

### 保守改造

不替换底层框架，不重写低代码控件，不改变业务 URL、权限、菜单、动态视图配置、表单提交和 Ajax 生命周期。

### 视觉统一

通过一个明确的桌面设计 token 层统一字体、字号、颜色、边框、圆角、阴影、间距、控件高度、hover/focus/disabled 状态。

### 工作台优先

BPMT 是后台工作系统，不做营销化 hero、强装饰、大面积渐变或过度卡片化。界面应安静、清晰、密度适中，便于重复操作和数据扫描。

### 旧控件新皮肤

继续复用 `ui-button`、`ui-dialog`、`ui-tabs`、`ui-styled-table`、`ztree`、`chosen`，但通过 CSS 覆盖让它们呈现更现代的视觉。

### 可回滚

第一阶段必须能通过移除一个 CSS 引入快速回滚。任何改变交互行为的改动都必须单独进入后续小版本。

## 视觉目标

### 信息密度

保持后台系统需要的高信息密度，但提升可读性：

- 正文默认 13px 或 14px。
- 表格行高建议 36px 到 40px。
- 输入框高度建议 30px 到 32px。
- 按钮高度建议 30px 到 32px。
- 左侧菜单点击目标高度建议不低于 28px。

### 色彩

推荐采用低饱和中性色工作台风格：

- 页面背景：`#f6f8fb` 或相近浅灰。
- 内容面板：白色。
- 主文本：`#1f2937`。
- 次文本：`#667085`。
- 边框：`#d9e2ec` 或 `#e5e7eb`。
- 主色：沉稳蓝或青蓝，避免大面积渐变。
- 危险色：红色只用于停用、删除、错误。
- 成功色：绿色只用于启用、通过、成功提示。

### 形态

- 圆角控制在 4px 到 6px。
- 面板可使用轻微阴影，但不做多层卡片嵌套。
- 表格以清晰分隔、hover 和表头层级为主，不依赖重边框。
- 不使用大面积拟物渐变。

### 字体

优先使用系统字体栈：

```css
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC",
  "Microsoft YaHei", Arial, sans-serif;
```

## 大版本范围

### 范围

- 桌面端登录页视觉刷新。
- 桌面端主框架视觉刷新，包括 topbar、header、横向域按钮、左侧菜单、footer。
- jQuery UI theme 覆盖，包括按钮、tab、dialog、accordion、datepicker 基础状态。
- `ws-table`、`ws-panel`、`ws-bar`、`ws-msg`、`ws-scroll` 视觉规范。
- zTree 菜单视觉覆盖。
- chosen 下拉视觉覆盖。
- 表单控件、textarea、只读、禁用、校验错误状态。
- 表格行操作 icon-only 规范。
- 高价值页面样本：登录页、首页、功能设置首页、第三方系统列表、AI 接入提示词弹窗、动态表开发列表、流程设置列表。
- Product Design 工作流文档化，支持后续持续审计、出图、原型和视觉 QA。

### 非范围

- 不升级 Java 8、Tomcat 7、Maven、MariaDB。
- 不升级 jQuery、jQuery UI、zTree、chosen、AmazeUI。
- 不引入 React、Vue、Tailwind、shadcn/ui 到主系统运行时。
- 不重写动态表、报表、流程、控件生成器。
- 不改移动端 H5。
- 不改权限模型、菜单模型、OAuth、API 鉴权。
- 不要求一次性替换全部 bitmap icon。

## Product Design 工作流接入

后续每个小版本都应使用 Product Design 插件形成可追溯设计证据：

1. `get-context`：确认当前小版本范围、页面样本、非范围。
2. `audit`：截图并审计当前线上或本地页面。
3. `ideate`：生成 3 个视觉方向，只做桌面端。
4. 选择方向后，用 Pencil 或 Product Design 原型能力产出关键页面稿。
5. `design-qa`：对照原始截图和目标稿检查间距、字号、层级、按钮状态。
6. 实现后再用 Playwright 截图比对，形成验收记录。

每个小版本至少要保留：

- 当前态截图。
- 目标态设计稿或说明。
- 实现后截图。
- 视觉 QA 结论。
- 风险和回滚说明。

## 总体验收标准

`v2.0.0` 完成时必须满足：

- 主系统桌面端不再呈现明显 jQuery UI 默认拟物风格。
- 登录页、主框架、左侧菜单、列表页、表单页、弹窗、分页、消息提示风格一致。
- 常用按钮有明确主次层级和 hover/focus/disabled 状态。
- 表格可读性明显提升，行操作可识别，分页不拥挤。
- 低代码动态页面未出现功能回归。
- 可通过关闭现代化 CSS 覆盖层快速定位样式问题。
- README、AGENTS 和维护文档记录主题开关、回滚方式和验收页面。
