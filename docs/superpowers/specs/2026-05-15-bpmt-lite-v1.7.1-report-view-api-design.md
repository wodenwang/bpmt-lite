# bpmt-lite v1.7.1 报表视图 API 设计

## 版本定位

`v1.7.1` 是基于 `v1.7.0` 的报表视图 API 补充版本。目标是把现有 `rep_list` 报表视图从“只能通过后台配置页面维护”推进到“可以通过公开 API 创建、导出、校验、全量替换、局部替换和删除配置”。

本版本整体设计参考 `v1.7.0` 动态表视图 API，但不抽象通用视图 API。接口形态保持同构，快照模型按报表视图底层模型单独设计。报表视图底层 source of truth 是 `VW_URL` 与 `VW_REPORT*`，不是 `VW_DYN_*`。

## 范围与非范围

### 本版本范围

- 新增 `report_views` API 模块。
- 对外开放 `viewClass=rep_list` 的报表视图完整配置快照。
- 支持从零创建报表视图。
- 支持导出现有报表视图快照，并保证导出的 JSON 可以作为 `PUT` 回写基线。
- 支持全量替换报表视图配置。
- 支持按 section 替换局部配置。
- 支持独立 `validate` 预检。
- 支持 `dryRun=true` 走真实写入前校验和写入计划生成路径，但不写库。
- 支持删除报表视图配置，删除必须带 `confirmViewKey`。
- 自动生成、保留和清理 API 管理范围内的 `CmPri` 权限资源。
- 对 SQL、脚本和按钮动作返回风险提示。
- 同步更新 runtime OpenAPI、人类 API 文档、版本归档 Markdown 和版本归档 OpenAPI JSON。

### 明确非范围

- 不覆盖 `dyn`、`flowbasic`、`note`、`viewer` 等其他视图类型。
- 不创建或修改菜单、首页卡片、外部 URL、按钮入口或其他发布入口。
- 不执行报表主 SQL、查询 SQL、约束 SQL、PK SQL 或按钮动作。
- 不承诺 SQL 语义、结果列、权限过滤或运行性能正确。
- 不管理报表业务数据 CRUD。
- 不删除报表 SQL 引用的业务表、业务数据或外部数据源。
- 不升级 Java、Tomcat、MariaDB、Maven 或前端技术栈。
- 不抽象 `/api/v1/views/{viewClass}` 之类的平台级通用视图配置 API。

## 现有链路摘要

当前后台配置链路如下：

1. `ViewConfigAction.submit()` 处理 `viewClass`、`loginType`、`description` 等门面字段。
2. `ViewConfigService.executeSaveConfig()` 或 `executeUpdateConfig()` 写入 `VW_URL`。
3. `ViewConfigService` 根据 `viewClass=rep_list` 找到 `ReportListViewAction`。
4. `ReportListViewAction` 构造或更新 `ReportListDataBuilder`。
5. `ReportListDataBuilder` 从 `RequestContext` 中读取 `config.*` 参数，写入 `VW_REPORT` 主配置。
6. `BaseDataBuilder.handleConfig()` 扫描并执行报表 handler：
   `ColumnsHandler`、`QuerysHandler`、`LimitsHandler`、`VarsHandler`、`SubsHandler`、`BtnsHandler`、`WeixinHandler`、`JsHandler`、`FrameSettingHandler`。
7. 各 handler 从页面 request 参数拼出 `VW_REPORT_*` 子配置和 `CmPri` 权限资源。

新 API 不复用后台页面 request 参数协议。它需要把报表视图配置沉淀为可以直接接收 JSON 快照的 API 服务层。

## 接口设计

### 接口清单

| 方法 | 路径 | 语义 |
| --- | --- | --- |
| `GET` | `/api/v1/report-views` | 分页查询 `rep_list` 报表视图摘要列表 |
| `POST` | `/api/v1/report-views` | 创建 `rep_list` 报表视图，body 为完整快照，可带 `dryRun=true` |
| `POST` | `/api/v1/report-views:validate` | 独立预检完整快照，不写库 |
| `GET` | `/api/v1/report-views/{viewKey}` | 导出完整快照 |
| `PUT` | `/api/v1/report-views/{viewKey}` | 全量替换报表视图配置，可带 `dryRun=true` |
| `PATCH` | `/api/v1/report-views/{viewKey}/{section}` | 替换单个配置区块，可带 `dryRun=true` |
| `DELETE` | `/api/v1/report-views/{viewKey}?confirmViewKey={viewKey}` | 删除报表视图配置 |

### section 枚举

`PATCH` 首版只支持 section 级替换，不支持单项级增删改。请求中没有出现的旧项视为删除。

允许的 `section`：

- `base`
- `columns`
- `queries`
- `limits`
- `variables`
- `subviews`
- `buttons`
- `weixin`
- `scripts`

### validate 与 dryRun

`validate` 是独立预检接口，适合 AI agent 在生成报表配置阶段校验完整快照。它不要求目标视图一定存在；如果传入 `viewKey` 且目标视图存在，应结合现有权限资源做更精确校验。

`dryRun=true` 用于 `POST`、`PUT`、`PATCH`。它必须走真实写入前同一条校验和写入计划路径，返回将要写入、更新、删除的底层配置摘要，但不写任何表。

## 完整快照模型

### 顶层字段映射

| 快照字段 | 底层映射 | 说明 |
| --- | --- | --- |
| `viewKey` | `VW_URL.VIEW_KEY`, `VW_REPORT*.VIEW_KEY` | 创建时可不传，由服务端生成；也可传入合法且唯一的稳定 key |
| `description` | `VW_URL.DESCRIPTION`, `VW_REPORT.DESCRIPTION` | 视图说明 |
| `loginRequired` | `VW_URL.LOGIN_TYPE` | `true` 映射系统用户登录，`false` 映射无需登录 |
| `base` | `VW_REPORT` | 展示名、数据源、主 SQL、主键传值、分页、排序 SQL、汇总 |
| `columns` | `VW_REPORT_COLUMN_SHOW`, `VW_REPORT_COLUMN_LINE` | 展示列、分割线、列表排序 |
| `queries` | `VW_REPORT_QUERY` | 查询条件、控件和 SQL 片段 |
| `limits` | `VW_REPORT_LIMIT` | 数据约束 SQL 片段 |
| `variables` | `VW_REPORT_EXEC_PREPARE` | 展示变量和数据准备脚本 |
| `subviews` | `VW_REPORT_SUB_VIEW` | 视图子标签 |
| `buttons` | `VW_REPORT_BTN_SYS`, `VW_REPORT_BTN_ITEM`, `VW_REPORT_BTN_SUMMARY` | 系统按钮、明细按钮、汇总按钮 |
| `weixin` | `VW_REPORT_WEIXIN` | 微信/H5 展示配置 |
| `scripts` | `VW_REPORT.LIST_JS_TYPE`, `VW_REPORT.LIST_JS_SCRIPT` | 列表页 JS |

### base

`base` 对应 `VW_REPORT` 主配置。

```json
{
  "displayName": "销售报表",
  "dbKey": null,
  "mainSql": {
    "type": 1,
    "script": "select * from SALE_ORDER where 1=1"
  },
  "primaryKey": {
    "value": {
      "type": 1,
      "script": "return vo.ID;"
    },
    "sql": {
      "type": 1,
      "script": "select * from SALE_ORDER where ID = ?"
    }
  },
  "layoutColumns": 2,
  "initQuery": true,
  "pagination": {
    "enabled": true,
    "pageLimit": 20
  },
  "summaryEnabled": false,
  "orderBySql": "CREATE_DATE desc"
}
```

规则：

- `displayName` 必填，映射 `BUSI_NAME`。
- `dbKey` 可为空，映射 `DB_KEY`。
- `mainSql.type` 与 `mainSql.script` 必填，映射 `MAIN_SQL_TYPE`、`MAIN_SQL_SCRIPT`。
- `primaryKey` 可为空；不为空时映射 `PK_TYPE`、`PK_SCRIPT`、`PK_SQL_TYPE`、`PK_SQL_SCRIPT`。
- `layoutColumns` 范围为 `1` 到 `5`。
- `initQuery=true` 映射 `INIT_QUERY=1`。
- `pagination.enabled` 映射 `PAGE_FLAG`。
- `pagination.pageLimit` 在启用分页时必填且大于 `0`。
- `summaryEnabled` 映射 `SUMMARY_FLAG`。
- `orderBySql` 映射 `ORDER_BY`，可为空。
- `VW_REPORT` 不持久化独立 `DIR` 字段，API 不单独提供 `direction` 字段；排序方向应写入 `orderBySql`。
- API 不执行 `mainSql`，也不验证 `orderBySql` 是否为真实字段或合法 SQL 片段。

### columns

`columns` 分为展示列、分割线和列表页顺序。

展示列映射 `VW_REPORT_COLUMN_SHOW`：

```json
{
  "stableKey": "ORDER_NO",
  "displayName": "订单号",
  "style": null,
  "wholeLine": false,
  "sortField": "ORDER_NO",
  "content": {
    "type": 1,
    "script": "return vo.ORDER_NO;"
  },
  "summaryContent": null,
  "permissions": {
    "view": null
  }
}
```

分割线映射 `VW_REPORT_COLUMN_LINE`：

```json
{
  "stableKey": "BASE_INFO",
  "displayName": "基础信息",
  "tip": {
    "type": 1,
    "script": "return '基础信息';"
  },
  "expanded": true,
  "permissions": {
    "view": null
  }
}
```

规则：

- `stableKey` 是 API 层用于权限保留和对象匹配的稳定键，不直接要求底层表存在同名字段。
- 数组顺序映射 `SORT`。
- `listOrder` 映射展示列的 `LIST_SORT`；未进入 `listOrder` 的展示列写入 `-1`。
- `content`、`summaryContent`、`tip` 都属于脚本风险字段，只做结构校验和风险提示。

### queries

`queries` 映射 `VW_REPORT_QUERY`。

```json
{
  "name": "customerName",
  "displayName": "客户名称",
  "widget": "text",
  "widgetParam": null,
  "defaultValue": null,
  "sql": {
    "type": 1,
    "script": "and CUSTOMER_NAME like concat('%', :customerName, '%')"
  },
  "description": null
}
```

规则：

- 同一视图内 `name` 不允许重复。
- 数组顺序映射 `SORT`。
- `widgetParam` 映射 `WIDGET_PARAM_TYPE`、`WIDGET_PARAM_SCRIPT`。
- `sql` 映射 `SQL_TYPE`、`SQL_SCRIPT`，只做结构校验和风险提示，不执行。
- 查询条件不支持 `permissions`；请求中出现非空 `permissions` 时返回 `REPORT_VIEW_UNSUPPORTED_PERMISSION`。

### limits

`limits` 映射 `VW_REPORT_LIMIT`。

```json
{
  "stableKey": "SELF_DEPARTMENT",
  "description": "仅看本部门",
  "sql": {
    "type": 1,
    "script": "and DEPT_ID = session.user.deptId"
  },
  "permissions": {
    "view": null
  }
}
```

规则：

- `description`、`sql.type`、`sql.script` 必填。
- 数组顺序映射 `SORT`。
- `sql` 只做结构校验和风险提示，不执行。
- `permissions.view` 映射 `PRI`。

### variables

`variables.prepared` 映射 `VW_REPORT_EXEC_PREPARE`。

```json
    "type": 1,
    "script": "return rows.sum { it.AMOUNT ?: 0 };"

```

规则：

- `var`、`exec.type`、`exec.script` 必填。
- 数组顺序映射 `SORT`。
- 变量不支持 `permissions`；请求中出现非空 `permissions` 时返回 `REPORT_VIEW_UNSUPPORTED_PERMISSION`。

## 校验规则

`validate` 与写接口共用同一套校验逻辑：

- `viewKey` 必须合法；创建时如果传入 `viewKey`，必须唯一。
- `viewKey` 为空时，服务端生成稳定 key。
- `base.displayName`、`base.mainSql.type`、`base.mainSql.script`、`base.layoutColumns`、`base.initQuery`、`base.pagination.enabled` 必填。
- `base.layoutColumns` 限制为 `1..5`。
- 启用分页时 `base.pagination.pageLimit` 必填且大于 `0`。
- `queries.name` 在同一视图内不允许重复。
- `mainSql`、`primaryKey.sql`、`queries.sql`、`limits.sql`、`columns.show.content`、`columns.show.summaryContent`、`variables.prepared.exec`、`buttons.*.param`、`scripts.list` 做结构校验和风险扫描，但不执行。
- `columns.show`、`columns.lines`、`queries`、`limits`、`variables.prepared`、`buttons`、`subviews` 的排序由数组顺序生成。
- 权限字段仅允许出现在底层有 `CmPri` 的对象上：展示列、分割线、约束、按钮、子视图、微信配置。
- 查询条件、变量和 SQL 本体不支持权限；请求中这些位置出现非空 `permissions` 时返回 `REPORT_VIEW_UNSUPPORTED_PERMISSION`。

## 权限资源策略

权限资源策略沿用动态表视图 API 的处理思想：

- 快照允许传入稳定权限 key，也允许为空。
- 为空时服务端为对应对象生成 `CmPri`。
- 全量替换时，优先按 `stableKey`、`name` 或旧对象顺序保留可匹配对象的旧权限资源。
- 删除对象时，同步删除该对象由 API 管理或本次替换确定不再引用的权限资源。
- 删除整个报表视图时删除 `VW_REPORT*` 配置和 API 管理范围内的权限资源。
- 删除报表视图不删除菜单、首页卡片、外部入口、业务表或业务数据。

## 风险提示

写接口和 `validate` 响应应返回 `warnings`。首版至少覆盖：

| code | 说明 |
| --- | --- |
| `SQL_SCRIPT_PRESENT` | 存在主 SQL、查询 SQL、约束 SQL 或 PK SQL |
| `CLIENT_SCRIPT_PRESENT` | 存在列表 JS、展示内容脚本、汇总内容脚本或提示脚本 |
| `BUTTON_ACTION_PRESENT` | 存在自定义按钮动作 |
| `EXTERNAL_DB_KEY_PRESENT` | 配置了非默认 `dbKey` |
| `UNEXECUTED_SQL_SEMANTICS` | API 未执行 SQL，不能保证 SQL 语义、结果列、权限过滤或运行性能正确 |

## 错误码

首批稳定错误码：

- `REPORT_VIEW_NOT_FOUND`
- `REPORT_VIEW_NOT_REP_LIST`
- `REPORT_VIEW_ALREADY_EXISTS`
- `REPORT_VIEW_INVALID_SNAPSHOT`
- `REPORT_VIEW_CONFIRM_REQUIRED`
- `REPORT_VIEW_UNSUPPORTED_PERMISSION`
- `REPORT_VIEW_UNSUPPORTED_SECTION`
- `REPORT_VIEW_INVALID_SQL_CONFIG`
- `REPORT_VIEW_INVALID_SCRIPT_CONFIG`

错误响应继续使用现有结构：

```json
{
  "success": false,
  "error": {
    "code": "REPORT_VIEW_INVALID_SNAPSHOT",
    "message": "报表视图快照校验失败。",
    "details": {},
    "requestId": "..."
  }
}
```

## 写入与删除边界

创建报表视图时写入：

- `VW_URL`
- `VW_REPORT`
- 需要的 `VW_REPORT_*` 子配置
- API 管理范围内的 `CmPri`

全量替换报表视图时：

- 更新 `VW_URL` 与 `VW_REPORT`。
- 删除并重建当前 API 管理范围内的 `VW_REPORT_*` 子配置。
- 尽量保留可匹配对象的旧权限资源。
- 对不可匹配且不再引用的权限资源执行清理。

局部替换 section 时：

- 从当前完整快照读取现有配置。
- 用请求 body 替换目标 section。
- 对合成后的完整快照执行同一套校验、权限处理和风险扫描。
- 只写入目标 section 相关底层配置及必要的 `VW_REPORT` / `VW_URL` 字段。

删除报表视图时：

- 必须传入 `confirmViewKey` 且与 path 中 `viewKey` 完全一致。
- 删除 `VW_URL`、`VW_REPORT`、`VW_REPORT_*` 子配置和 API 管理范围内的权限资源。
- 返回明确标志：`businessDataDeleted=false`、`menuDeleted=false`、`externalEntriesDeleted=false`。

## 与动态表视图 API 的差异

- `dynamic-table-views` 管理 `viewClass=dyn`，`report-views` 管理 `viewClass=rep_list`。
- 动态表视图核心是 `base.tableName`，报表视图核心是 `base.mainSql`。
- 报表视图没有 `fields.formFields`，因为它不是动态表 CRUD 表单。
- 报表视图没有 `processors.before/after`，只有 `variables.prepared`。
- 报表视图不执行 DDL，不修改动态表结构。
- 报表视图的 SQL 和按钮动作风险更高，文档必须显式说明 API 不执行 SQL 语义验证。
