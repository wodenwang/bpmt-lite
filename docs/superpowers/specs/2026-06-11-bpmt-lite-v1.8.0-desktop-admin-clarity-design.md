# bpmt-lite v1.8.0 桌面后台清晰度基线设计

## 版本定位

`v1.8.0` 重新定位为桌面后台清晰度基线，不再作为 CSS-only 现代化主题基础版本。

本版本的目标不是“让旧后台看起来更现代”，而是让三个代表性桌面任务更清楚、更可操作、更可验证：

1. 登录后首页识别当前工作状态。
2. 第三方系统列表完成接入配置入口认知。
3. AI 接入提示词弹窗完成复制接入说明任务。

## Product Design 结论

旧 `modern-theme foundation` 分支的视觉验证失败。失败原因是方向问题，不是细节问题：

- 页面浅色化后仍然缺少任务解释。
- 顶部、模块、树菜单和主内容层级没有重新组织。
- 空状态、加载状态和错误状态仍然像旧控件输出。
- 旧图标和表格布局继续主导体验。
- 验收只证明页面能打开，没有证明用户任务更清楚。

因此，新版本必须先做产品结构和状态语义，再做视觉统一。

## 用户与场景

### 系统管理员

- 进入后台后定位功能模块。
- 管理第三方系统、用户权限、动态表和流程配置。
- 需要快速判断页面状态和下一步操作。

### 业务管理员

- 查看待办、公告和工作量。
- 进入业务表和流程办理页面。
- 需要高密度但清楚的列表、表单和弹窗。

### 外部集成开发者

- 阅读 API docs。
- 获取 OAuth 与 AI 接入提示词。
- 需要明确复制、配置和验证路径。

## 设计原则

### 后台可信感

界面应像长期运行的企业管理系统：克制、稳定、清晰、密度合理。不做营销化视觉，不使用大面积渐变、装饰性插画或过度卡片化。

### 当前任务优先

每个页面必须优先呈现：

- 页面标题。
- 页面用途。
- 当前状态。
- 主操作。
- 次操作。
- 异常时的下一步。

### 旧控件可用化

继续保留 jQuery UI、zTree、chosen、`ws-table`、`ws-panel`、`ws-bar`，但要求它们表达清楚的产品语义：

- `ws-panel` 是内容分组，不是装饰卡片。
- `ws-table` 是扫描和录入工具，不是页面布局万能容器。
- zTree 是导航，不是图标陈列。
- 弹窗是短任务容器，不是大页面搬进浮层。

### 渐进实现

允许少量 JSP 属性和 class 辅助 CSS 表达状态，但不改变业务提交、Ajax 生命周期、菜单权限、动态视图模型和 API 鉴权。

## 页面设计

### 登录后首页

#### 当前问题

- 顶部状态句信息过多。
- 模块按钮与左树同时抢注意力。
- 主内容 panel 里只有旧式 loading 条，缺少状态语义。
- footer 固定在底部，视觉存在感偏强。

#### 目标

- 用户进入系统后能快速判断当前账号、当前模块和待办状态。
- loading、empty、error 状态必须有文字解释。
- 左侧树用于定位，主内容用于工作状态，不互相竞争。

#### 设计要求

- 顶部状态区弱化为账户/组织/操作入口。
- 当前模块有稳定高亮。
- 左侧当前菜单和当前路径可识别。
- 首页 panel 标题简洁，内容区必须支持加载中、无数据、加载失败。

### 第三方系统列表

#### 当前问题

- 空数据时只显示空表头和分页。
- 页面缺少“第三方系统是什么”的说明。
- 新增按钮位置在表格右侧，用户需要先理解空表再找到主操作。
- 搜索区仍像表格录入区，主次按钮弱。

#### 目标

第三方系统列表应成为外部系统接入配置的清楚入口。

#### 设计要求

- 页面标题为“第三方系统”。
- 页面说明必须覆盖 OAuth 接入、微信登录和 AI 接入提示词。
- 主操作“新增外部系统”应在页面标题区或表格工具栏中明确呈现。
- 搜索区应与结果区视觉分离。
- 空状态至少区分无数据、无匹配结果、无权限。
- 分页在无数据时不应成为主要视觉焦点。

### AI 接入提示词弹窗

#### 当前问题

- 弹窗内容结构仍像 table form。
- 左侧 label 与大 textarea 的关系 awkward。
- 复制按钮缺少成功/失败反馈。
- 大文本区域缺少只读、复制、全选等任务暗示。

#### 目标

弹窗应支持一个清晰短任务：复制给第三方 AI agent 或集成开发者。

#### 设计要求

- 标题为“AI 接入提示词”。
- 副说明解释用途。
- 提示词区域应为只读大文本。
- 主操作为“复制提示词”。
- 必须有复制成功、复制失败反馈。
- 关闭是次操作。
- 内容高度不应撑出 1440x900 视口。

## 状态规范

### Loading

- 文案必须说明正在加载什么。
- 超过合理时间应有失败/重试路径。
- 不继续使用无语义的条纹 loading 作为唯一状态。

### Empty

- 无数据：说明当前还没有配置，并给出主操作。
- 无匹配：说明筛选无结果，并给出重置查询。
- 无权限：说明当前账号无法查看，并指向授权路径或管理员。

### Error

- 必须说明失败对象和可尝试动作。
- 不暴露敏感错误栈。
- 必要时保留 requestId 或日志定位信息。

### Success

- 操作成功必须给出短反馈，例如复制成功、保存成功、启用成功。
- 反馈不能只靠颜色。

## 视觉方向候选

Product Design 后续 `ideate` 只探索以下三种方向，不再做泛化“现代主题”：

| 方向 | 说明 | 适用性 |
| --- | --- | --- |
| 运营控制台 | 强调任务区、状态区、主操作和清晰空态。 | 推荐，最符合本轮目标。 |
| 企业配置台 | 强调密集表格、稳定表单、审计感和权限感。 | 适合功能设置、第三方系统、权限配置。 |
| 轻量开发者控制台 | 强调 API、OAuth、AI 接入说明和复制配置。 | 适合第三方系统和 API docs，不能泛化到全后台。 |

最终实现前必须选择其中一个主方向，或明确组合边界。

## 文件范围

第一阶段允许影响：

```text
docs/v2.0.0/*
docs/superpowers/specs/*
docs/superpowers/plans/*
platform/src/main/webapp/xhtml/frame/frame.jsp
platform/src/main/webapp/xhtml/thirdpart/ThirdpartAction/list.jsp
platform/src/main/webapp/xhtml/thirdpart/ThirdpartAction/aiPrompt.jsp
platform/src/main/webapp/css/frame.css
platform/src/main/webapp/css/styles.css
platform/src/main/webapp/css/styles_light.css
```

是否继续保留或重写：

```text
platform/src/main/webapp/css/bpmt-modern.css
```

必须在实现前重新决定。它不再是默认发布目标。

## 非范围

- 不改移动端 H5。
- 不升级前端依赖。
- 不改 OAuth 协议。
- 不改 API 鉴权。
- 不改动态表/报表/流程业务逻辑。
- 不更新镜像 tag、release 说明或安装脚本，直到新方向通过。
- 不把 API docs 强行并入后台 shell。

## 验收证据

进入实现前必须有：

- 当前态截图：沿用 `docs/v2.0.0/screenshots/v1.8.0/*`。
- 目标态视觉稿：Product Design ideate、Pencil 或 prototype 输出。
- 差异说明：当前态问题、目标态解决方式、实现风险。

实现后必须有：

- 1440x900 实现态截图。
- 关键交互操作记录。
- console error 检查。
- Maven 编译结果。
- 回滚说明。

## 完成标准

- 登录后首页不再只是旧 panel + loading 条。
- 第三方系统列表空态能指导用户新增或重置查询。
- AI 接入提示词弹窗能清楚完成复制任务并给出反馈。
- 顶部和左侧导航不抢主内容。
- 新样式不造成按钮换行、文本重叠、弹窗溢出。
- 旧 `modern-theme foundation` 不再作为后续 agent 默认实现依据。
