# bpmt-lite v1.8.1 前端缺陷加固计划

## Goal

`v1.8.1` 是基于 `v1.8.0 desktop admin clarity baseline` 的补丁版本。目标是把 v1.8.0 暴露出的前端缺陷归拢到 `v1.8.*` 修复线中，优先处理不改变业务逻辑、但明显影响可用性和可访问性的桌面后台问题。

## Design brief

- 产品：`bpmt-lite` 桌面后台。
- 目标用户：系统管理员、业务管理员、外部集成开发者。
- 视觉来源：v1.8.0 实现态、既有 JSP/jQuery UI/zTree/chosen 控件体系、`docs/v2.0.0/screenshots/v1.8.0-clarity-implemented/`。
- 交互要求：真实系统可运行，可通过浏览器和 Maven 编译验证。
- 版本约束：所有前端缺陷修复归入 `v1.8.*`，本轮使用 `v1.8.1`；不升级前端技术栈，不重写低代码控件，不改移动端 H5。

## 调查结论

### P1: icon-only 按钮缺少稳定可识别说明

旧后台大量使用 `text="false"` 图标按钮。v1.8.0 只在第三方系统代表路径局部补了 `title/aria-label`，分页、动态表、工作流待办、邮件列表等通用按钮仍可能在 DOM 中缺少可访问名称。

修复策略：在通用 jQuery UI button 初始化层读取按钮原始文本，自动补齐缺失的 `title` 和 `aria-label`。

### P1: 第三方系统“重置查询”不能清空当前筛选并重新加载

v1.8.0 空状态文案提示用户点击“重置查询”，但按钮使用 `type="reset"`。当服务端用当前 query 参数回填表单时，浏览器 reset 会回到当前筛选值，不会清空并提交，导致用户仍停留在无匹配状态。

修复策略：改为显式 `resetThirdpartQuery` 动作，清空文本和 select，再提交列表表单。

### P2: AI 接入提示词弹窗缺少底部关闭动作，复制异常路径反馈不完整

v1.8.0 依赖标题栏关闭按钮；对部分 `navigator.clipboard.writeText` 异常返回路径没有稳定反馈。

修复策略：补充底部“关闭”次操作，统一复制失败兜底为选中文本并提示手动复制。

### P2: focus、disabled、分页布局状态仍不够硬

v1.8.0 已有输入和按钮 focus，但链接、左侧树节点、禁用按钮和分页条在密集页面中仍容易不清楚；分页条使用 float/absolute 的旧布局，窄内容区可能和记录数说明重叠。

修复策略：在 `bpmt-modern.css` 中补齐链接/树节点 focus、禁用按钮状态和 `.ws-bar.page` flex 布局覆盖。

### P1: 通用查询表单仍使用浏览器 reset，多个页面会复现筛选清不掉

`form[query=true]` 在动态表、工作流、报表、邮件、管理配置等页面广泛存在。旧 `Core.initAfter` 对 reset 按钮只阻止默认行为并重新初始化控件，没有清空当前服务端回填的 query 值，也没有重新提交查询。

修复策略：新增 `Core.resetQueryForm($form)`，仅对 `query="true"` 表单生效；清空文本、textarea、select、checkbox，重置 `_page/_field/_dir`，然后提交表单。非查询表单继续保持原有 `Widget.initAll($form)` 行为。

### P1: 动态表、工作流、报表和待办列表缺少空结果解释

第三方系统列表已有无匹配空状态，但低代码高频列表仍只显示表头和分页。用户无法判断是没有数据、筛选过严、权限不足还是加载失败。

修复策略：在动态表列表、工作流列表、报表列表和待办列表补 `bpmt-state-empty`，文案统一说明“当前查询条件没有返回记录”，并提示调整筛选或重置查询。

### P2: 全局提示和确认弹窗缺少稳定语义

旧页面大量使用 `Ui.msg`、`Ui.alert` 和 `Ui.confirm` 承载错误、确认和保存反馈。原实现只呈现视觉弹窗/消息，缺少 `role`、`aria-live` 和关闭按钮可访问名称，键盘和辅助技术用户不容易判断当前反馈状态。

修复策略：在 `ws-ui.js` 通用层为区域消息补 `role=status/alert` 与关闭按钮 `title/aria-label`，为 alert/confirm 弹窗补 `role=alert/alertdialog` 和 `aria-live`。

### P2: 后台管理列表继续存在空表格状态

邮件、微信应用、公众号、定时任务、队列、数据表和视图配置等管理列表仍然只渲染表头和底部操作条。筛选无结果时，管理员无法快速判断是无数据、筛选过严还是页面加载异常。

修复策略：为这些高频管理列表补 `bpmt-state-empty` 空状态，沿用 v1.8.1 统一的“调整筛选或重置查询”反馈模式；同时在 `Core.initAfter` 增加窄范围兜底，只对带 `form` 绑定且包含排序/勾选表头的 `ws-table` 自动补通用空状态。

### P2: 新登录页表单标签和登录动作语义不完整

`frame_new/login.jsp` 的用户名、密码和验证码 label 仍是空 `for`，登录动作使用链接模拟按钮且缺少空格键触发；验证码图片也没有说明。键盘用户和辅助技术用户无法稳定理解输入框和登录动作。

修复策略：关联 label 与输入框，补充 autocomplete 和验证码说明；为登录链接补 `role=button`、`tabindex`、`aria-label` 和空格/回车触发，并移除遗留 `console.log()`。
