# bpmt-lite v1.7.2 GitHub Issue Bugfixes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 `v1.7.2` 收敛为基于 `v1.7.1` 的补丁版本，优先修复当前 GitHub open issues `#14`、`#15`、`#17`，不新增业务功能。

**Architecture:** 本版本只修复已发布功能的阻断缺陷：报表视图 API 写入默认值、动态/报表视图 API 写入后的 Hibernate/Hazelcast 缓存失效、数据库操作 `save` 对非自增主键 INSERT 的兼容、控制面板版本信息来源。API 路径和响应结构保持兼容，文档只更新版本、已修复问题和验收说明。

**Tech Stack:** Java 8、Maven 3、Tomcat 7、Hibernate 4、Hazelcast Hibernate cache、JUnit 4、Docker Compose、GHCR multi-arch images。

## 当前 Issue 基线

截至 2026-05-16 当前打开的 GitHub issue：

- `#17`：`v1.7.1 report view API create returns 500 after validate/dryRun pass`
- `#15`：`Dynamic table view API updates do not invalidate runtime view cache`
- `#14`：`控制面板中的注册信息没有显示实际的bpmt-lite版本`

`#17` 正文还记录了同一轮测试发现的 `POST /api/v1/database-operations/save` 对字符串主键或无自增主键 INSERT 返回 500 的问题。本计划将其纳入 `v1.7.2`，作为 `#17` 的附带修复项处理。

public void evictEntityRegions(String... entityNames) {

private String resolvePlatformVersion(Attributes mainAttribs) {

Create `platform/src/test/java/com/riversoft/platform/PlatformVersionTest.java`:

package com.riversoft.platform;

import org.junit.Test;

import java.lang.reflect.Method;
import java.util.jar.Attributes;

import static org.junit.Assert.assertEquals;

public class PlatformVersionTest {
    @Test
    public void resolvesVersionFromManifestImplementationVersion() throws Exception {
        Attributes attributes = new Attributes();
        attributes.putValue("Implementation-Version", "1.7.2");
        Platform platform = newPlatformForTest();

        assertEquals("1.7.2", resolve(platform, attributes));
    }

    @Test
    public void fallsBackToSystemPropertyWhenManifestVersionMissing() throws Exception {
        String old = System.getProperty("bpmt.version");
        System.setProperty("bpmt.version", "1.7.2-test");
        try {
            Platform platform = newPlatformForTest();
            assertEquals("1.7.2-test", resolve(platform, new Attributes()));
        } finally {
            if (old == null) {
                System.clearProperty("bpmt.version");
            } else {
                System.setProperty("bpmt.version", old);
            }
        }
    }

    private static Platform newPlatformForTest() throws Exception {
        java.lang.reflect.Constructor<Platform> constructor =
                Platform.class.getDeclaredConstructor(java.io.File.class);
        constructor.setAccessible(true);
        return constructor.newInstance(new java.io.File(System.getProperty("java.io.tmpdir")));
    }

    private static String resolve(Platform platform, Attributes attributes) throws Exception {
        Method method = Platform.class.getDeclaredMethod("resolvePlatformVersion", Attributes.class);
        method.setAccessible(true);
        return (String) method.invoke(platform, attributes);
    }
}
```

- `POST /api/v1/database-operations/save`：兼容字符串主键或无自增主键 INSERT；无 generated key 时返回 `id: null`，不再返回 500。

## 文档入口

- API 文档：`/api/docs/`
- OpenAPI：`/api/openapi.json`
```

`v1.7.2` 是基于 `v1.7.1` 的 GitHub issue bugfix 补丁版本。

## 修复内容

- 修复 #17：报表视图 API `validate` / `dryRun` 通过但真实创建返回 500。
- 修复 #17 附带问题：数据库操作 `save` 对字符串主键或无自增主键 INSERT 返回 500。
- 修复 #15：动态表视图 API 写入后运行期页面仍读取旧缓存，需要重启才生效。
- 修复 #14：控制面板版本信息不显示实际 `bpmt-lite` 版本。

## 验收命令

```bash
export JAVA_HOME=/Library/Java/JavaVirtualMachines/jdk-1.8.jdk/Contents/Home
export PATH="$JAVA_HOME/bin:$PATH"
mvn -s settings.local.xml -pl api -Dtest='ReportView*Test,DynamicTableView*Test,DatabaseOperationServiceTest,OrmReportViewRepositoryTest' test
mvn -s settings.local.xml -pl platform -Dtest=PlatformVersionTest test
mvn -s settings.local.xml -DskipTests compile
scripts/verify-repo.sh
scripts/build-image.sh
scripts/build-api-image.sh
```
