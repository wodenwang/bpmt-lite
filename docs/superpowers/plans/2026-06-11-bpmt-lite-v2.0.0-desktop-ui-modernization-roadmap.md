# bpmt-lite v2.0.0 桌面端 UI 现代化路线图

> 状态：本计划中的 `v1.8.0 CSS-only 主题基础` 已被 Product Design 判定为方向失败。后续实现应使用 `docs/superpowers/plans/2026-06-11-bpmt-lite-v1.8.0-desktop-admin-clarity.md`。本文保留为旧路线记录。

## Goal

把 `bpmt-lite` 桌面端 UI 从历史 jQuery UI 后台推进到更清楚的企业后台体验，同时保持 Java 8、JSP、jQuery UI、zTree、chosen、低代码控件和动态视图体系稳定。

## Architecture

采用渐进式覆盖架构：

```text
jquery-ui theme
  -> jquery-ui-ext.css
  -> styles.css
  -> styles_light.css / styles_dark.css
  -> bpmt-modern.css
```

`bpmt-modern.css` 作为桌面现代化覆盖层，优先覆盖既有选择器，不改控件初始化逻辑。只有当 CSS 无法表达必要语义时，才在后续版本补少量 JSP 属性，例如 `title`、`aria-label`、额外 class 或状态标记。

## 版本路线

### v1.8.0: 桌面后台清晰度基线

目标：以三条代表路径验证任务清晰度收益，不再以 CSS-only 全局主题作为发布目标。

文档：`docs/v2.0.0/desktop-admin-clarity-replan.md`

预期改动：

- 重新确认 Product Design 方向。
- 围绕登录后首页、第三方系统列表、AI 接入提示词弹窗建立当前态、目标态、实现态证据。
- 补页面标题、说明、空状态、复制反馈和主次操作层级。
- 不改业务逻辑、不改权限模型、不改控件生成。

必验页面：

- 登录后首页。
- 第三方系统列表。
- AI 接入提示词弹窗。

完成标准：

- 用户认可目标态方向。
- 三条代表路径可正常加载和操作。
- Playwright 桌面截图留档，覆盖当前态、目标态、实现态。
- `mvn -s settings.local.xml -DskipTests compile` 通过，或说明未运行原因。

### v1.8.1: 视觉 QA 与可访问性加固

目标：补齐 `v1.8.0` 暴露出的低风险问题，建立桌面 UI QA 清单。

文档：`docs/v2.0.0/v1.8.1-visual-qa-a11y-hardening-design.md`

预期改动：

- 补充 focus-visible、disabled、error、warning、success 状态。
- 为高频 icon-only 操作补 `title` 或 `aria-label`。
- 修复 footer 压内容、loading 层、弹窗关闭按钮可见性等问题。
- 建立 `docs/v2.0.0/desktop-ui-qa-checklist.md`。

必验页面：

- 第三方系统列表行操作。
- 动态表开发列表。
- 流程设置列表。
- 典型表单保存页。
- 典型错误提示页。

完成标准：

- 键盘 Tab 可看到焦点。
- icon-only 按钮有可识别说明。
- 常见禁用态和错误态不再只依赖颜色或旧图标。

### v1.9.0: 桌面壳层与导航刷新

目标：在不改变菜单数据和权限模型的前提下，提升主框架观感与导航效率，并集中修复已经确认的全局前端缺陷。

文档：`docs/v2.0.0/v1.9.0-desktop-shell-navigation-design.md`

预期改动：

- 优化 topbar 登录信息、右侧操作入口、模块 tab、logo 区。
- 优化左侧 zTree 菜单层级、选中态、hover、展开收起视觉。
- 弱化或重构固定 footer 的视觉存在感。
- 明确 `frame` 与 `frame_new` 的后续路线：统一样式或逐步收敛。
- 建立全局弹窗 z-index 层级，修复部分按钮高于遮罩或窗体的问题。
- 统一 jQuery UI 弹窗右上角关闭按钮尺寸。
- 修复默认无结果、后续查询有结果时空状态与结果表格同时出现的问题。
- 重新设计 logo 区、菜单区、顶部功能按钮区、主功能展示区的高度、宽度和边界对齐。
- 将 zTree hover 尺寸稳定规则从左侧菜单扩展到全站非菜单 zTree。

必验页面：

- 我的事项首页。
- 功能设置模块。
- 基础数据模块。
- 左侧菜单长列表滚动状态。
- 第三方系统列表和 AI 接入提示词弹窗。
- 至少一个确认/提示弹窗。
- 至少一个非菜单 zTree 页面。
- 一个空状态和查询结果互相切换的列表页。

完成标准：

- 当前模块、当前菜单、当前位置能被清楚识别。
- topbar 不再像浏览器插件条或系统日志条。
- footer 不遮挡主要工作区。
- 弹窗遮罩和窗体能覆盖普通按钮、顶部按钮、列表行操作和 zTree。
- 抽样弹窗右上角关闭按钮尺寸一致。
- 查询结果有数据时不再残留“没有匹配的数据”空状态。
- 四区布局在 1440x900、1366x768 和较窄桌面视口下边界对齐。
- 菜单 zTree 和非菜单 zTree hover/focus 不改变节点宽高。

### v1.9.1: 列表/表单/弹窗体验 polish

目标：针对低代码后台最常用的三类界面做工作效率优化。

文档：`docs/v2.0.0/v1.9.1-list-form-dialog-polish-design.md`

预期改动：

- 搜索区视觉分组和按钮位置统一。
- 表格列头、长文本、时间、状态字段样式统一。
- 行操作按钮组规范化。
- 表单 label、输入框、提示、错误、必填标记统一。
- 弹窗标题、内容、底部操作统一。

必验页面：

- 第三方系统列表与弹窗。
- 动态表开发列表和表单。
- 流程设置列表和配置弹窗。
- 用户权限页面。

完成标准：

- 列表页主操作和次操作一眼可分。
- 表单字段对齐稳定，不因控件类型变化而跳动。
- 弹窗内容区不再呈现旧式表格拼装感。

### v2.0.0: 现代后台体验基线收敛

目标：把前面版本沉淀为正式桌面 UI 基线和后续开发规范。

文档：`docs/v2.0.0/v2.0.0-modern-admin-experience-design.md`

预期改动：

- 固化 `bpmt-modern.css` 的 token、组件覆盖和注释结构。
- 补充 README、AGENTS、维护文档。
- 清理不再推荐的旧主题选项说明。
- 建立后续新页面的 UI 规范：按钮、表格、表单、弹窗、空态、错误态。

完成标准：

- 后续新功能默认使用现代化样式基线。
- 旧 theme 仍可作为兼容 fallback，但不作为推荐视觉。
- 有完整截图证据和回滚说明。

## Product Design 阶段节奏

每个小版本开始前：

- 使用 Product Design `get-context` 锁定版本范围。
- 使用 Product Design `audit` 捕获当前态截图。
- 使用 Product Design `ideate` 生成 3 个桌面视觉方向。
- 用户确认方向后，再进入 Pencil 或 prototype。

每个小版本实现前：

- 选定一组代表页面。
- 形成目标态截图或静态稿。
- 明确 CSS-only、JSP 属性补充、JS 行为变更三类边界。

每个小版本完成前：

- 使用 Playwright 截图验证桌面视口。
- 使用 Product Design `design-qa` 对照目标稿。
- 使用 gstack `/review` 做代码风险审查。
- 使用 gstack `/ship` 做最终收口。
