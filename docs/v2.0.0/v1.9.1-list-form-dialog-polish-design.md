# v1.9.1 列表、表单与弹窗体验 polish 设计

## 版本定位

`v1.9.1` 聚焦后台系统最高频的工作界面：列表页、搜索区、表单页、弹窗和分页。它不改变低代码控件协议，而是在既有 DOM 和选择器上统一视觉规范。

全局弹窗遮罩层级、弹窗右上角关闭按钮尺寸、空状态与结果表格同时出现、四区 shell 对齐、全站 zTree hover 变形等已确认缺陷归入 `v1.9.0`。`v1.9.1` 只在这些基础稳定后继续细化列表、表单、弹窗内容区和分页体验。

## 目标

- 列表页更易扫描。
- 搜索区更清楚。
- 表单字段更稳定对齐。
- 弹窗更像现代后台组件。
- 主操作、次操作、危险操作更容易区分。

## 非目标

- 不改动态表配置模型。
- 不改表单提交协议。
- 不改分页参数。
- 不改搜索参数命名。
- 不改控件 JS 生命周期。

## 列表页规范

### 搜索区

当前搜索区通常由 `table.ws-table` 生成，label 和控件混在同一个表格里。建议：

- 搜索区使用浅色背景块。
- label 固定宽度并右对齐。
- 输入框高度 32px。
- 查询按钮使用主按钮。
- 重置按钮使用次按钮。
- 高级查询或展开按钮保持弱视觉。

### 表格

- 表头使用浅灰背景和中等字重。
- 数据行高度 36px 到 40px。
- hover 使用轻背景。
- 数字和时间列保持右对齐。
- 状态列可使用轻量 badge，但不要改变文本语义。
- 长 URL 或长 ID 默认截断并保留 title。

### 行操作

- 行操作 icon-only 允许保留。
- 按钮尺寸固定 28px 到 32px。
- 每个按钮必须有 `title` 或 `aria-label`。
- 危险操作 hover 不应只靠红色，建议同时使用 title 和确认弹窗。

## 表单规范

- label 宽度稳定。
- input/select/textarea 高度和边框统一。
- 必填标记统一。
- 错误提示显示在字段附近。
- readonly 与 disabled 明确区分。
- 大 textarea 用等宽或清晰正文风格。
- 保存、提交、取消、重置按钮位置统一。

## 弹窗规范

- 标题栏高度稳定。
- 关闭按钮可见，hover 明确。
- 内容区 padding 16px 到 20px。
- 底部按钮区与内容区分隔。
- 主按钮和次按钮层级明确。
- 大文本弹窗支持滚动，不能撑出视口。

## 分页规范

- 页码和前后翻页按钮不应过度拟物。
- 当前页与 disabled 状态清晰。
- 每页记录数、总页数、总记录数文案保持可读。
- 分页条右侧按钮和左侧统计信息垂直居中。

## 代表页面

- 第三方系统列表。
- 动态表开发列表。
- 数据字典列表。
- 流程设置列表。
- 用户权限。
- AI 接入提示词弹窗。
- 流程配置弹窗。

## 文件影响

优先修改：

```text
platform/src/main/webapp/css/bpmt-modern.css
```

可能少量修改：

```text
platform/src/main/webapp/xhtml/common/page_bar.jsp
platform/src/main/webapp/xhtml/thirdpart/ThirdpartAction/list.jsp
```

不应修改：

```text
platform/src/main/webapp/js/ws-core.js
platform/src/main/webapp/js/jquery-ui-ext.js
```

除非 CSS 无法满足必要状态。

## 验收标准

- 列表页主操作一眼可见。
- 搜索区和表格区视觉分离。
- 表格长文本不破坏布局。
- 行操作按钮可识别。
- 表单 label 和控件对齐稳定。
- 弹窗不遮挡、不溢出、不显得像嵌套表格堆叠。

## Product Design 输入

建议 Product Design `audit` 先按任务流捕获：

1. 打开功能设置。
2. 进入第三方系统。
3. 查询。
4. 打开 AI 接入提示词弹窗。
5. 关闭弹窗。

再使用 `ideate` 针对列表、表单、弹窗三类组件生成视觉方向。
