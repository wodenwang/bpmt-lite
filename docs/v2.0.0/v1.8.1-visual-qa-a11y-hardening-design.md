# v1.8.1 视觉 QA 与可访问性加固设计

## 版本定位

`v1.8.1` 是 `v1.8.0` 的补丁版本，用于修复现代化主题基础落地后暴露出的可见问题，并补齐低风险可访问性和 QA 规则。

## 目标

- 建立桌面 UI QA 清单。
- 补齐 focus、hover、active、disabled、readonly、error 状态。
- 为高频 icon-only 按钮补充可识别说明。
- 修复现代化 CSS 带来的明显错位、遮挡和对比度问题。

## 非目标

- 不重新设计壳层结构。
- 不替换图标系统。
- 不重写表单和表格组件。
- 不做移动端。

## 主要问题类型

### 查询重置没有真正清空筛选

第三方系统列表的无匹配空状态提示用户点击“重置查询”，但旧 `type="reset"` 会回到服务端渲染时的当前 query 值，不会清空筛选并重新加载。

`v1.8.1` 应把这类“重置”从浏览器 reset 改为显式清空并提交。

### 焦点不可见

旧系统大量依赖鼠标操作。现代化后必须保证键盘 Tab 时能看到焦点，尤其是：

- 登录输入框和登录按钮。
- topbar 链接。
- 模块按钮。
- 左侧菜单节点。
- 表格行操作按钮。
- 弹窗关闭按钮和底部按钮。

### icon-only 不可识别

现有按钮大量使用：

```jsp
<button icon="wrench" text="false">编辑</button>
```

按钮文本被 jQuery UI 隐藏后，视觉只剩旧图标。`v1.8.1` 应优先补：

- `title`
- `aria-label`
- tooltip 稳定显示策略

### 状态只靠颜色

启用、停用、错误、警告、禁用不能只靠颜色，应至少增加：

- 文案。
- icon。
- 边框或背景。
- 禁用态透明度和 cursor。

### footer 遮挡

当前 footer 固定在底部，可能遮挡表格、图表或弹窗底部。`v1.8.1` 应检查：

- 页面滚动到底部时内容是否被挡。
- 弹窗底部按钮是否被挡。
- 图表 legend 是否被挡。

## QA 清单结构

新增：

```text
docs/v2.0.0/desktop-ui-qa-checklist.md
```

建议包含：

- 页面加载状态。
- 桌面视口截图。
- 顶部导航状态。
- 左侧菜单状态。
- 表格扫描性。
- 表单对齐。
- 弹窗遮罩、关闭和复制操作。
- 键盘焦点。
- disabled 状态。
- error 状态。
- 空数据状态。

## 代表页面

- 第三方系统列表：行操作、搜索、分页。
- AI 接入提示词弹窗：输入、复制、关闭。
- 动态表开发列表：密集低代码列表。
- 流程设置：复杂按钮和配置入口。
- 登录页：表单焦点和错误提示。

## 验收标准

- 代表页面键盘 Tab 焦点可见。
- icon-only 按钮在 DOM 中有 `title` 或 `aria-label`。
- 筛选无结果后，“重置查询”能清空筛选并回到默认列表状态。
- AI 接入提示词弹窗底部有明确关闭动作，复制失败时会选中文本并提示手动复制。
- 禁用按钮视觉明显，不被误认为可点击。
- 错误提示颜色和文案都可见。
- footer 不遮挡主要内容。
- QA 清单随版本提交。

## Product Design 输入

建议使用 Product Design `audit` 对比 `v1.8.0` 实现后截图，重点检查：

- 控件状态是否一致。
- 点击目标是否过小。
- 表格是否拥挤。
- 弹窗层级是否清楚。
- 视觉对比度是否足够。
