# v2.0.0 现代后台体验基线收敛设计

## 版本定位

`v2.0.0` 是桌面端 UI 现代化大版本的正式收敛版本。它不是一次新的大范围重构，而是把 `v1.8.x` 和 `v1.9.x` 已验证的现代化样式、组件规范、QA 清单和维护规则固化为默认基线。

## 目标

- 固化现代化 CSS 覆盖层。
- 固化桌面后台 UI 规范。
- 更新 README、AGENTS、维护文档。
- 明确后续新页面和新功能的 UI 默认规则。
- 保留可回滚策略和旧主题兼容说明。

## 非目标

- 不引入新前端框架。
- 不删除旧 theme 资源。
- 不一次性替换所有 icon。
- 不迁移移动端。
- 不重写低代码控件。

## 设计系统收敛

### 文件结构

推荐形成：

```text
platform/src/main/webapp/css/bpmt-modern.css
docs/v2.0.0/desktop-ui-guidelines.md
docs/v2.0.0/desktop-ui-qa-checklist.md
docs/v2.0.0/screenshots/
```

### CSS 分区

`bpmt-modern.css` 建议按以下顺序组织：

```text
1. 设计 token 注释或 CSS variables
2. 基础 typography
3. 页面壳 frame
4. jQuery UI 基础覆盖
5. BPMT ws-* 控件覆盖
6. 表格
7. 表单
8. 按钮
9. tabs / dialog / accordion
10. zTree / chosen
11. 状态与无障碍
12. 兼容补丁
```

## 后续页面开发规则

### 按钮

- 列表行内操作可以使用 icon-only，但必须有 `title` 或 `aria-label`。
- 非行内场景优先使用 icon + 文案。
- 按钮文案不得换行。
- 查询、提交、保存使用主按钮。
- 重置、取消、刷新使用次按钮。
- 删除、停用等危险操作必须有确认机制。

### 表格

- 操作列宽度必须明确。
- 时间列右对齐。
- 状态列使用文本或轻量 badge。
- 长 URL、长 ID、长说明需要截断和 title。
- 空数据必须有空态，不只显示空表格。

### 表单

- label、控件、提示、错误信息对齐稳定。
- 必填状态统一。
- disabled 和 readonly 视觉不同。
- 大字段使用 textarea 或代码区样式。

### 弹窗

- 弹窗不应无限制撑高。
- 底部操作区统一。
- 关闭按钮必须可见。
- 弹窗标题应简洁描述任务。

## 发布标准

- 所有必验页面有 1440x900 截图。
- Product Design `design-qa` 无关键视觉阻塞。
- Playwright 手动路径验证通过。
- Maven 编译通过。
- Docker 或线上环境完成 smoke。
- 回滚方式明确。

## 回滚策略

优先回滚：

```text
platform/src/main/webapp/include/html_include.jsp 中 bpmt-modern.css 引入
```

如果某些 JSP 属性补充导致问题，应单独回滚对应页面，不影响全局 CSS。

## Product Design 后续用法

`v2.0.0` 之后，新增 UI 功能默认流程：

1. 用 Product Design `audit` 查找相似页面。
2. 按 `desktop-ui-guidelines.md` 设计。
3. 如有新组件，先出 3 个视觉方向。
4. 选定后做 prototype 或 Pencil。
5. 实现后用 `design-qa` 和 Playwright 截图验收。
