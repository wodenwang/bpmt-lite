## 结论

第 2 步 `gstack /plan-design-review` 通过，但带有明确约束：`v1.9.0` 不能只做壳层视觉微调。它必须先修复全局层级、空状态刷新和 zTree 尺寸稳定，再把四区布局收拢成可理解的导航侧栏和工作区。

当前设计完整度：`7/10`。

达到 `10/10` 需要补齐：

- Pencil 或等价目标态原型，至少覆盖登录后首页、功能设置、第三方系统弹窗和非菜单 zTree。
- 明确 shell 栅格尺寸：侧栏宽度、顶部高度、主内容起点、footer 占位和窄桌面行为。
- 明确 modal 层级 token 和 `z-index` 阶梯。
- 明确空状态刷新生命周期，覆盖 Ajax 更新、查询、分页和排序。
- 明确全站 zTree 基础规则和菜单 zTree 的局部差异。

## 关键发现

### P0：先定义全局层级，再修弹窗遮罩

`frame.css` 中 `.frame.topbar` 和 `.frame.footer` 使用固定定位和 `z-index: 99`。旧 jQuery UI theme、dialogExtend、chosen、顶部按钮和行操作也可能各自设置层级。若继续逐个按钮调低层级，后续仍会复发。

设计要求：

- 在 `bpmt-modern.css` 顶部注释中定义层级阶梯。
- `.ui-widget-overlay` 必须高于 fixed shell、chosen、zTree、表格按钮和顶部按钮。
- `.ui-dialog` 必须高于 overlay。
- dialogExtend 的 titlebar buttonpane 和最小化容器不得破坏 modal 层级。

用户影响：弹窗打开后，用户不能看到或误点背后的按钮。

### P0：空状态刷新必须按生命周期设计

`Core.applyEmptyTableState` 当前发现 `.bpmt-empty-table-row` 后直接返回。这个逻辑适合首次补空状态，但不适合查询结果从空变为有数据的场景。

设计要求：

- 每次 `Core.initAfter(zone)` 都重新判断数据行。
- 有数据时移除当前表格下的 `.bpmt-empty-table-row`。
- 无数据时再插入空状态。
- 判断数据行时继续排除嵌套表格和表头行。

用户影响：查询有结果时不能继续显示“没有匹配的数据”。

### P0：四区布局要从视觉归属上重组

当前四区是 logo、菜单、顶部功能按钮、主内容。问题不是四区存在，而是四区像四个独立块。只修高度和宽度会让错位减少，但不会让用户更清楚当前位置。

设计要求：

- logo + 菜单形成左侧导航侧栏。
- 顶部功能按钮 + 主内容形成右侧工作区。
- 侧栏宽度、顶部高度、主内容左边界和 footer 占位必须成组定义。
- 目标态原型应明确当前模块、当前菜单、当前页面标题三层定位。

用户影响：进入系统后能一眼判断当前模块和工作区，不需要从多个区域拼上下文。

### P1：全站 zTree 基础规则要先于菜单样式

`v1.8.1` 已修复左侧菜单 zTree hover 晃动，但问题范围已经扩大到非菜单 zTree。若继续只写 `#frame-menu-panel .ztree`，权限树、组织树、分类树仍会抖动。

设计要求：

- 全站 `.ztree li a` 默认态预留透明边框。
- hover、selected、focus 不改变节点宽高、line-height、padding。
- switch、checkbox、radio、icon 不因 hover 改变布局。
- 菜单 zTree 的颜色和当前态在基础规则之后局部覆盖。

用户影响：树节点 hover 不再晃动，权限和组织类页面的点击目标稳定。

### P1：关闭按钮统一是组件问题，不是单个弹窗问题

AI 提示词弹窗、`Ui.alert`、`Ui.confirm`、`Ajax.win` 和 dialogExtend 都可能生成标题栏按钮。关闭按钮尺寸不统一会让弹窗看起来不可信，也降低点击稳定性。

设计要求：

- 统一 `.ui-dialog-titlebar-close` 宽高和图标居中。
- 同步覆盖 `.ui-dialog-titlebar-buttonpane` 内按钮。
- focus 和 hover 不改变尺寸。
- 抽样覆盖提示、确认和业务弹窗。

## 原型要求

第 3 步 Pencil 原型应聚焦四个画面：

1. 登录后首页：导航侧栏、顶部功能按钮、主内容区、footer 占位。
2. 功能设置模块：当前模块、当前菜单、长菜单滚动、主内容起点。
3. 第三方系统弹窗：遮罩、窗体、关闭按钮、背后按钮不可穿透。
4. 非菜单 zTree：含 checkbox 或组织/权限树的 hover、selected、focus 稳定态。

原型不需要探索业务表格细节。表格、表单、分页的视觉 polish 留到 `v1.9.1`。
