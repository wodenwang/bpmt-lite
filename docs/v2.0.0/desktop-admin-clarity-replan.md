# 桌面后台体验重新规划：Admin Clarity Baseline

## 结论

`v1.8.0 modern-theme foundation` 方向停止继续推进。

该方向的核心假设是：在不改变结构的前提下，用一个 CSS-only 覆盖层就能显著改善桌面后台观感。当前截图验证说明这个假设不成立。页面确实变浅、变白、变圆角，但用户任务没有更清楚，旧后台的信息架构、状态表达和操作路径仍然主导体验。

新的方向改为：

```text
v1.8.0 desktop admin clarity baseline
```

中文名称：桌面后台清晰度基线。

它不是视觉翻新版本，而是一个后台可用性版本：先让用户知道自己在哪、当前页面是什么、现在是什么状态、下一步能做什么，再逐步做视觉统一。

## Product Design brief

- 产品：`bpmt-lite` 桌面后台。
- 目标用户：系统管理员、业务管理员、外部集成开发者。
- 当前视觉来源：本仓当前运行截图、旧 BPMT 后台结构、现有 JSP/jQuery UI/zTree/chosen 控件体系。
- 目标感受：可信、克制、密度合理、适合长期运维的企业后台，而不是新 SaaS 营销感。
- 交互级别：第一阶段为可运行的真实系统 vertical slice，不做静态演示稿替代实现。
- 非目标：不改移动端 H5，不升级前端技术栈，不重写低代码控件，不重写菜单/权限/表单提交模型。

## 旧方向失败原因

### 1. 主题覆盖没有解决产品语义

登录后首页、功能设置、第三方系统列表和弹窗的主要问题不是颜色陈旧，而是页面缺少任务解释和状态解释。例如第三方系统列表为空时，用户看到的是空表头、分页和新增按钮，但不知道：

- 当前页面用于配置什么。
- 当前为空是因为没有数据、没有权限、筛选条件过严，还是加载失败。
- 下一步应该新增外部系统，还是先调整权限/初始化数据。

### 2. 壳层信息层级仍然混乱

顶部状态句、模块按钮、左侧树、主内容面板同时争夺注意力。CSS 改浅以后，旧结构仍然明显：用户、组织、角色、日期、待办、全屏、设置、退出混在同一条线上，当前模块和当前位置没有形成稳定层级。

### 3. 旧控件视觉被保留，但没有被产品化

zTree 图标、jQuery UI tabs、旧式 loading bar、table form、icon-only 按钮仍然在关键路径中出现。它们可以继续使用，但需要被重新定义成清楚的后台控件，而不是只换颜色。

### 4. “现代化”目标过宽

旧路线把登录页、首页、列表、弹窗、API docs 都放进同一个 CSS-only 主题目标，导致验收标准变成“看起来更现代”，而不是“某条用户任务明显更好完成”。

### 5. Product Design 证据链不够硬

旧路线保留了截图，但缺少“当前态 -> 目标态 -> 实现态”的对照。截图证明页面能打开，不足以证明体验方向正确。

## 新设计原则

### 任务优先

每个页面先回答四个问题：

- 我在哪。
- 这个页面做什么。
- 当前系统处于什么状态。
- 下一步最合理的操作是什么。

### 结构先于皮肤

优先重整壳层、页面标题、当前路径、主操作、空状态、加载状态和错误状态。颜色、圆角、阴影只服务这些结构。

### 保留后台密度

BPMT 不是消费级产品，不追求大留白、大卡片、大 hero。列表、树和表单可以保持密集，但必须更好扫描、更好点击、更好理解。

### 渐进驯化旧控件

不替换 jQuery UI、zTree、chosen、低代码控件。先定义它们在后台中的角色和状态：

- 树菜单用于定位。
- 表格用于扫描和操作。
- 表单用于配置。
- 弹窗用于短任务。
- loading、empty、error、no-permission 都必须有清晰文案和动作。

### 代表路径先行

不再做全局主题铺开。先选三条高频路径做样板：

1. 登录后首页：让管理员进入系统后明确当前工作区和待处理状态。
2. 功能设置 -> 第三方系统列表：让配置型页面有清楚标题、说明、搜索、空状态和主操作。
3. 第三方系统 -> AI 接入提示词弹窗：让弹窗中的长文本复制任务更顺手，有反馈、有关闭路径。

## 新版本拆分

| 版本 | 名称 | 目标 | 是否继承旧 CSS-only 方向 |
| --- | --- | --- | --- |
| `v1.8.0` | desktop admin clarity baseline | 三条代表路径的清晰度样板 | 否，重开方向 |
| `v1.8.1` | state and accessibility hardening | loading、empty、error、focus、icon label | 部分复用可接受的样式片段 |
| `v1.9.0` | shell and navigation clarity | 顶部、当前位置、模块、左树、footer | 不以皮肤为主 |
| `v1.9.1` | list form dialog clarity | 列表、搜索、表单、弹窗、分页 | 从代表路径扩展 |
| `v2.0.0` | enterprise admin experience baseline | 固化设计系统和维护规则 | 只固化已验证模式 |

## v1.8.0 新范围

### 必做

- 停止把 `bpmt-modern.css` 作为发布目标。
- 保留当前截图作为失败方向证据。
- 重新定义桌面后台 shell 的页面层级。
- 给第三方系统列表增加页面标题、说明、空状态、主操作层级和搜索区结构规范。
- 给 AI 接入提示词弹窗增加明确任务文案、复制反馈和长文本区域规则。
- 建立 Product Design 对照证据：当前态截图、目标态稿、实现态截图。

### 可做

- 少量 JSP 属性补充，例如 `title`、`aria-label`、状态 class。
- 少量 CSS 调整，用于服务明确的结构目标。
- 保留旧路线中确实有效的局部样式，例如更清楚的按钮边框、表格表头和弹窗边界。

### 不做

- 不发布一个全局“现代主题”。
- 不一次性覆盖所有 jQuery UI 控件。
- 不替换全部图标。
- 不重写 zTree。
- 不为了视觉统一大幅改变低代码页面 DOM。
- 不更新版本号、镜像 tag、release 文档，直到新方向通过设计评审。

## 目标态页面结构

### 登录后首页

目标：从“模块和树堆叠”变成“进入系统后的工作状态概览”。

建议结构：

- 顶部低噪声账号区。
- 明确的当前模块。
- 左侧菜单保持树，但强化当前路径。
- 主内容第一屏展示待办、公告、工作量的真实状态。
- loading 必须有超时和失败提示，不再只有旧式条纹。

### 第三方系统列表

目标：从“空表格”变成“第三方接入配置入口”。

建议结构：

- 页面标题：第三方系统。
- 说明：配置外部系统 OAuth 接入、微信登录和 AI 接入提示词。
- 主操作：新增外部系统。
- 搜索区：系统标识、系统名称、Client ID、启用状态。
- 空状态：
  - 无数据：还没有外部系统，新增后可生成 OAuth 和 AI 接入说明。
  - 有筛选：没有匹配结果，建议重置查询。
  - 无权限：提示联系管理员授权。

### AI 接入提示词弹窗

目标：从“长 textarea”变成“复制接入说明的短任务”。

建议结构：

- 标题：AI 接入提示词。
- 副说明：用于复制给第三方 AI agent 或集成开发者。
- 内容区：只读大文本，支持全选和复制。
- 主操作：复制提示词。
- 反馈：复制成功、复制失败、浏览器不支持。
- 次操作：关闭。

## Product Design 后续流程

1. `get-context` playback：使用本文作为 brief。
2. `research`：补充 issue、截图和内部文档证据。
3. `ideate`：针对三条代表路径生成 3 个方向，不做全系统皮肤。
4. 用户选择方向后，用 Pencil 或 prototype 做关键屏目标态。
5. `design-qa`：当前态截图和目标态稿并排比较。
6. 通过后再进入实现计划。

## 判定标准

新方向只有在满足以下条件时才进入实现：

- 用户能一眼看出当前页面的任务。
- 空状态、加载状态、无权限状态有明确下一步。
- 主操作和次操作不需要靠猜。
- 顶部和左侧导航不抢主内容注意力。
- 三条代表路径都有目标态视觉证据。
- 实现范围能控制在一个 vertical slice 内。
