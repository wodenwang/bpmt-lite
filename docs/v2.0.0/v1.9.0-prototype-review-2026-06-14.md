## 对五个 bug 的原型映射

### 1. 弹框遮罩挡不住高层级按钮

证据：`03 Modal layering`。

目标态：

- 页面内存在“历史高层级按钮”。
- 全局遮罩覆盖整个 shell。
- 弹框窗体位于遮罩之上。

工程含义：

- 定义统一 layer ladder。
- `.ui-widget-overlay` 必须高于 fixed shell、chosen、zTree、表格按钮和顶部按钮。
- `.ui-dialog` 必须高于 `.ui-widget-overlay`。

### 2. 弹框右上角按钮大小不一

证据：`03 Modal layering`。

目标态：

- `Dialog Close Button 32` 固定 `32 x 32`。
- close 图标居中，hover/focus 不改变按钮尺寸。

工程含义：

- 覆盖 `.ui-dialog-titlebar-close`。
- 同步覆盖 dialogExtend titlebar buttonpane 内按钮。

### 3. 空状态和结果表格同时存在

证据：`01 Home shell`。

目标态：

- 结果表格区域明确写入“有结果时不保留没有匹配的数据行”。
- 空状态由当前查询结果驱动，不由首次初始化状态驱动。

工程含义：

- 修复 `Core.applyEmptyTableState`。
- 每次 `Core.initAfter(zone)` 都重新判断当前表格数据行。
- 有数据时删除当前表格下已有 `.bpmt-empty-table-row`。

### 4. logo、菜单、顶部按钮、主内容四区不对齐

证据：`01 Home shell`、`02 Settings shell`。

目标态：

- logo 和菜单合并为统一左侧导航侧栏。
- 顶部功能按钮和主内容属于右侧工作区。
- 侧栏宽度、顶部高度、主内容起点统一。

工程含义：

- 先用 CSS 收拢视觉归属，不改菜单权限和 zTree 数据。
- frame JSP 只在必要时补语义 class，避免重写 frame 结构。

### 5. 非菜单 zTree hover 尺寸变形

证据：`02 Settings shell`、`04 Non-menu zTree`。

目标态：

- hover 前后 row height 固定为 `32px`。
- switch、ico、a 的盒模型不改变。
- 菜单 zTree 可以保留深色视觉，但应继承同一尺寸基础规则。

工程含义：

- 先写全站 `.ztree` 基础尺寸规则。
- 再写菜单 zTree 局部颜色和当前态覆盖。

## 进入工程评审的约束

1. 不升级前端技术栈。
2. 不替换 zTree、jQuery UI dialog、旧 table/form 输出。
3. 不修改权限、菜单数据、路由、OAuth、API 或数据库。
4. `v1.9.0` 的首个 vertical slice 应优先修复全局 bug，而不是先做大面积 shell 视觉重组。
5. Playwright 验证必须覆盖桌面 `1440x900`、`1366x768`，以及弹框、空状态、非菜单 zTree 三类状态。
