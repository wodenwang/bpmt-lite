# v1.9.0 桌面壳层与导航刷新设计

## 版本定位

`v1.9.0` 聚焦桌面主框架、导航体验和已知全局前端缺陷修复。它在 `v1.8.x` 桌面后台清晰度基线之上，进一步优化 logo 区、菜单区、顶部功能按钮区、主内容区和 footer，同时收口弹窗层级、弹窗关闭按钮、空状态刷新和全站 zTree hover 变形等问题。

本版本不是全站视觉翻新，也不是列表/表单/弹窗的完整 polish。它的目标是先把桌面后台 shell 的四区布局和全局交互缺陷修到稳定可用，再进入 `v1.9.1` 的列表、表单、弹窗细化。

## 设计评审状态

2026-06-14 已完成 `gstack /plan-design-review` 只读评审。评审结论见：

```text
docs/v2.0.0/v1.9.0-plan-design-review-2026-06-14.md
```

评审后的执行方向：

- 先做全局层级和状态机制，再做局部页面样式。
- 四区布局采用“导航侧栏 + 工作区”整合方向，不再只微调每个区域的边距。
- 弹窗、空状态和全站 zTree 属于 `v1.9.0` 必修缺陷，不能降级到 `v1.9.1`。
- Product Design / Pencil 原型应聚焦 shell 结构，不探索业务表格细节。

## 目标

- 让当前用户、当前模块、当前菜单、当前页面更容易识别。
- 让 logo 区、菜单区、顶部功能按钮区、主功能展示区的高度、宽度、边界和视觉层级保持一致。
- 降低 topbar 和 footer 的视觉噪音，并把 logo、顶部按钮与菜单从视觉上更深度整合成一个稳定后台壳层。
- 提升左侧树菜单和全站其他 zTree 的层级可读性、点击目标和 hover/focus 稳定性。
- 全局修复弹窗遮罩与窗体压不住高层级按钮的问题。
- 统一弹窗右上角关闭按钮尺寸。
- 修复查询结果从无数据切换为有数据时，空状态与结果表格同时出现的问题。
- 保持原有菜单数据、权限模型和 URL 跳转逻辑。

## 非目标

- 不改菜单权限模型。
- 不改域和菜单的生成方式。
- 不改 zTree 插件。
- 不引入新路由。
- 不改移动端 H5 frame。
- 不做 `v1.9.1` 范围内的全量列表、表单、分页和业务弹窗视觉 polish。
- 不改变查询接口、分页参数、表单提交协议或低代码控件生成协议。

## 当前结构

主框架来自：

```text
platform/src/main/webapp/xhtml/frame/frame.jsp
platform/src/main/webapp/css/frame.css
```

关键结构：

- `.frame.topbar`
- `.frame.header`
- `.frame.menu`
- `.frame.main`
- `.frame.footer`

当前视觉问题集中在四区边界：

- logo 区和顶部功能按钮区高度不同步，导致壳层像被拆成两段。
- 左侧菜单区和主功能展示区顶部基线不稳定，切换模块或页面后容易出现错位感。
- 菜单区与顶部区域的背景、边框和阴影缺少统一归属，用户难以判断哪些区域属于导航，哪些区域属于业务内容。
- footer 虽已在 `v1.8.1` 中修复遮挡和漂浮问题，但仍应在 `v1.9.0` 中确认它不会破坏主框架高度计算。

## 已知缺陷必须修复

### 1. 弹窗遮罩和窗体层级不足

问题：弹框时，部分按钮的 CSS 层级高于遮罩或窗体，导致按钮浮在弹窗之上。

要求：

- 全局梳理 jQuery UI dialog、遮罩、旧按钮条、chosen、zTree、顶部功能按钮、行操作按钮的 `z-index` 层级。
- 建立明确层级阶梯：普通页面 < 固定 shell < 下拉/浮层 < modal overlay < modal dialog < modal 内部控件。
- 不通过给单个业务按钮临时加更高层级解决；必须从全局层级模型修复。
- 验收时至少覆盖 AI 接入提示词弹窗、确认弹窗、包含高层级按钮的列表页和顶部功能按钮可见场景。

### 2. 弹窗右上角关闭按钮尺寸不统一

问题：不同弹框右上角关闭按钮大小不一，部分旧 jQuery UI dialog 标题栏关闭按钮与新版弹窗按钮尺寸不一致。

要求：

- 统一 `.ui-dialog-titlebar-close` 的宽高、内边距、图标居中、hover/focus 状态。
- 关闭按钮视觉尺寸不得随标题栏高度、字体、旧 icon sprite 或 button 初始化差异变化。
- 验收时覆盖 `Ui.alert` / `Ui.confirm`、AI 接入提示词弹窗和至少一个旧业务配置弹窗。

### 3. 空状态与结果表格同时出现

问题：默认查询结果区域无数据时显示空状态，后续查询有结果后，空状态没有被清理，导致“没有匹配的数据”和结果表格同时存在。

要求：

- 修复通用空状态兜底逻辑，让它在 Ajax 更新、查询提交、分页、排序或列表重绘后重新判断当前结果。
- 当结果行数大于 0 时必须移除或隐藏空状态。
- 当结果行数为 0 时才显示空状态。
- 不允许只修某一个 JSP；应优先修 `Core.applyEmptyTableState` 或等价通用初始化路径。
- 验收时覆盖默认空列表 -> 查询有结果 -> 再次查询无结果 -> 重置查询的完整切换链路。

### 4. 四区布局对齐与视觉整合不足

问题：页面架构被拆成 logo 区、菜单区、顶部功能按钮区、主功能展示区四个独立区域，本身合理，但目前高度、宽度和边界不对齐。

要求：

- 重新设计 shell 栅格：logo 区与顶部功能按钮区在同一水平基线，菜单区与主内容区在同一垂直边界。
- 菜单区和 logo 区应形成统一导航侧栏，顶部功能按钮区和主内容区应形成统一工作区。
- 明确侧栏宽度、顶部栏高度、主内容起点、滚动区域和 footer 占位。
- 优先通过 CSS 和少量 JSP class/结构标记实现，不重写 frame 跳转逻辑。
- 验收时覆盖 1440x900、1366x768、Codex 右侧窄浏览器视口，以及长菜单滚动场景。

### 5. 非菜单 zTree hover 尺寸变形

问题：`v1.8.1` 已修复左侧菜单 zTree hover 晃动，但系统中菜单之外的 zTree 仍存在 hover 后尺寸变形。

要求：

- 全局修正 `.ztree` 默认、hover、selected、focus 状态，默认态必须预留透明边框或等价尺寸空间。
- 不只覆盖 `#frame-menu-panel`；权限树、组织树、用户树、分类树等非菜单 zTree 必须一起受益。
- 保留 zTree 原有缩进、switch icon、checkbox/radio icon 和节点图标，不替换插件。
- 验收时覆盖左侧菜单 zTree、用户权限/组织类 zTree、包含 checkbox 的 zTree。

## 评审后设计决策

### D1. Shell 结构方向

采用“统一导航侧栏 + 统一工作区”的方向。

- logo 区和菜单区归为同一个导航侧栏视觉系统。
- 顶部功能按钮区和主内容区归为同一个工作区视觉系统。
- 允许保留现有 DOM 和跳转逻辑，但 CSS 上要形成稳定的侧栏宽度、顶部高度和主内容起点。
- 不采用只修 margin/padding 的方式，因为它无法解决四个区域视觉割裂的问题。

### D2. Modal 层级模型

采用全局层级阶梯，不做逐按钮补丁。

建议层级语义：

```text
ordinary content < fixed shell < dropdown/floating controls < modal overlay < modal dialog < modal internal controls
```

实现计划中需要把该阶梯映射到 `bpmt-modern.css` 注释和选择器。所有局部 `z-index` 修复必须符合该阶梯，不得让普通按钮超过 modal overlay。

### D3. 空状态刷新机制

采用通用初始化路径修复，优先处理 `Core.applyEmptyTableState`。

当前 `Core.applyEmptyTableState` 在发现 `.bpmt-empty-table-row` 时直接返回。这会导致默认空列表经过 Ajax 或查询变成有数据后，旧空状态仍可能残留。`v1.9.0` 计划必须要求：

- 每次初始化先重新计算真实数据行。
- 有数据时清理或隐藏 `.bpmt-empty-table-row`。
- 无数据时再补空状态。
- 不把修复限制在第三方系统某一个 JSP。

### D4. zTree 覆盖范围

采用全站 `.ztree` 基础尺寸稳定规则，再用局部选择器补差异。

- 基础规则覆盖所有 zTree。
- `#frame-menu-panel` 只负责菜单侧栏专属颜色、当前态和密度。
- 非菜单 zTree 仍保留业务树特征，例如 checkbox、radio、组织树图标和节点图标。
- 验收必须包含至少一个非菜单 zTree，不得只看左侧菜单。

## topbar 设计

当前 topbar 把登录信息和操作入口放在 30px 灰色条中，容易显得像系统日志。建议：

- 登录信息改为低对比文本。
- 右侧入口保持文字，但增加 hover/focus 状态。
- 当前用户、组织、角色信息可以弱化为一行状态说明。
- 退出、设置等操作不要使用红色 hover，避免误导。
- topbar 应与 logo 区共享统一高度或统一基线，避免形成上下错位的两套导航。

## header 与模块按钮

当前横向模块按钮是 jQuery UI buttonset 风格。建议：

- 保留横向模块入口。
- 当前模块使用主色细边或浅色背景。
- 非当前模块使用纯白或透明背景。
- 模块按钮之间保持 4px 间距，不再连成强拟物按钮组。
- icon 可暂时保留，后续再统一替换。
- 顶部功能按钮区的 z-index 不得高于 modal overlay 或 modal dialog。

## 左侧菜单

当前 zTree 菜单层级依赖缩进和小图标。建议：

- 一级菜单字体稍重。
- 二级菜单普通字重。
- 当前菜单使用主色背景或左侧 3px 竖条。
- hover 使用浅灰或浅蓝背景。
- 点击目标高度增加到 28px 左右。
- 面板标题“菜单”弱化，不占过多高度。
- 左侧菜单区应与 logo 区合并成统一侧栏视觉，不再像独立浮动面板。
- 菜单 zTree 的 hover、selected、focus 尺寸必须与默认态一致。

## 全站 zTree

`v1.9.0` 不只处理左侧菜单 zTree。所有 `.ztree` 都应使用统一基础规则：

- 默认态、hover 态、selected 态、focus 态不改变节点宽高。
- 默认态预留透明边框或等价空间。
- `switch`、`icon`、`button`、checkbox/radio 图标不因 hover 改变布局。
- 业务树可在局部追加颜色和密度，但不得覆盖基础尺寸稳定规则。

## footer

当前固定 footer 会压住内容。建议路线：

1. `v1.9.0` 先视觉弱化并确保不遮挡。
2. 如确认无兼容风险，再改为普通流式 footer 或状态栏。

footer 不应成为页面主视觉的一部分。

## 主内容区

- `.frame.main` 保持现有 margin 结构。
- 主内容背景与页面背景区分。
- tab 容器应减少边框嵌套。
- 页面空态应有更清楚的提示，不只显示“没有首页标签”。
- 主内容区与顶部功能按钮区应形成统一工作区，左边界、右边界和滚动区域必须稳定。
- 列表 Ajax 更新后，空状态必须与实际结果同步，不能与数据行同时存在。

## 弹窗层级与关闭按钮

- 建立全局 modal z-index token 或注释清楚的固定层级。
- `.ui-widget-overlay` 必须盖住普通按钮、顶部按钮、列表行操作和 zTree。
- `.ui-dialog` 必须盖住 overlay。
- `.ui-dialog-titlebar-close` 使用统一尺寸和居中规则。
- 弹窗内按钮可以有正常 focus/hover，但不得突破 dialog 层级。

## 验收页面

- 我的事项首页。
- 功能设置首页。
- 基础数据模块。
- DEMO 展示模块。
- 左侧菜单长列表展开状态。
- 第三方系统列表和 AI 接入提示词弹窗。
- 至少一个 `Ui.alert` / `Ui.confirm` 触发页面。
- 至少一个非菜单 zTree 页面，例如用户权限、组织、角色或分类树。
- 一个默认无结果、查询后有结果、再次无结果的列表页。

## 验收标准

- 当前模块可被一眼识别。
- 当前菜单可被一眼识别。
- topbar 不抢主内容注意力。
- footer 不遮挡主内容。
- 左侧菜单点击目标更易操作。
- 菜单跳转和 Ajax 加载逻辑不变。
- 弹窗遮罩和窗体能压住所有普通页面按钮、顶部按钮和行操作按钮。
- 所有抽样弹窗右上角关闭按钮尺寸一致。
- 查询结果有数据时不显示“没有匹配的数据”空状态。
- logo 区、菜单区、顶部功能按钮区、主功能展示区在目标视口下高度和边界对齐。
- 菜单 zTree 和非菜单 zTree hover/focus 不发生宽高变化。

## Product Design 输入

建议 Product Design `ideate` 只探索壳层，不探索业务表格：

```text
为 bpmt-lite 桌面后台壳层生成 3 个视觉方向。必须保留 topbar、logo、横向模块按钮、左侧树菜单、主内容区结构。不要移动端，不重写导航，不改权限模型。目标是安静、现代、适合企业后台。
```
