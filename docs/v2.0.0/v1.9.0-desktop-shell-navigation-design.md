# v1.9.0 桌面壳层与导航刷新设计

## 版本定位

`v1.9.0` 聚焦桌面主框架和导航体验。它在 `v1.8.x` 现代化主题基础上，进一步优化 topbar、header、横向模块按钮、左侧菜单、主内容区和 footer。

## 目标

- 让当前用户、当前模块、当前菜单、当前页面更容易识别。
- 降低 topbar 和 footer 的视觉噪音。
- 提升左侧树菜单的层级可读性和点击目标。
- 保持原有菜单数据、权限模型和 URL 跳转逻辑。

## 非目标

- 不改菜单权限模型。
- 不改域和菜单的生成方式。
- 不改 zTree 插件。
- 不引入新路由。
- 不改移动端 H5 frame。

## 当前结构

主框架来自：

```text
platform/src/main/webapp/xhtml/frame/frame.jsp
platform/src/main/webapp/css/frame.css
```

关键结构：

- `.frame.topbar`
- `.frame.header`
- `.frame.menu`
- `.frame.main`
- `.frame.footer`

## topbar 设计

当前 topbar 把登录信息和操作入口放在 30px 灰色条中，容易显得像系统日志。建议：

- 登录信息改为低对比文本。
- 右侧入口保持文字，但增加 hover/focus 状态。
- 当前用户、组织、角色信息可以弱化为一行状态说明。
- 退出、设置等操作不要使用红色 hover，避免误导。

## header 与模块按钮

当前横向模块按钮是 jQuery UI buttonset 风格。建议：

- 保留横向模块入口。
- 当前模块使用主色细边或浅色背景。
- 非当前模块使用纯白或透明背景。
- 模块按钮之间保持 4px 间距，不再连成强拟物按钮组。
- icon 可暂时保留，后续再统一替换。

## 左侧菜单

当前 zTree 菜单层级依赖缩进和小图标。建议：

- 一级菜单字体稍重。
- 二级菜单普通字重。
- 当前菜单使用主色背景或左侧 3px 竖条。
- hover 使用浅灰或浅蓝背景。
- 点击目标高度增加到 28px 左右。
- 面板标题“菜单”弱化，不占过多高度。

## footer

当前固定 footer 会压住内容。建议路线：

1. `v1.9.0` 先视觉弱化并确保不遮挡。
2. 如确认无兼容风险，再改为普通流式 footer 或状态栏。

footer 不应成为页面主视觉的一部分。

## 主内容区

- `.frame.main` 保持现有 margin 结构。
- 主内容背景与页面背景区分。
- tab 容器应减少边框嵌套。
- 页面空态应有更清楚的提示，不只显示“没有首页标签”。

## 验收页面

- 我的事项首页。
- 功能设置首页。
- 基础数据模块。
- DEMO 展示模块。
- 左侧菜单长列表展开状态。

## 验收标准

- 当前模块可被一眼识别。
- 当前菜单可被一眼识别。
- topbar 不抢主内容注意力。
- footer 不遮挡主内容。
- 左侧菜单点击目标更易操作。
- 菜单跳转和 Ajax 加载逻辑不变。

## Product Design 输入

建议 Product Design `ideate` 只探索壳层，不探索业务表格：

```text
为 bpmt-lite 桌面后台壳层生成 3 个视觉方向。必须保留 topbar、logo、横向模块按钮、左侧树菜单、主内容区结构。不要移动端，不重写导航，不改权限模型。目标是安静、现代、适合企业后台。
```
